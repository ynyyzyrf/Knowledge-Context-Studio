# 內建 OpenViking 交付

使用者已確認：取得 Knowledge Context Studio 後即可安裝、配置、啟停及升級完整產品，無須另行取得 OpenViking 倉庫或部署另一套引擎。

採用產品內建元件方案：API、worker、PostgreSQL、引擎由同一入口管理；引擎保留私有程序與資料卷，不暴露主機端口。產品適配層與權限契約不變。這不是同程序嵌入。

## 需求與驗收

1. 只需 Python 3.12+、Docker Compose V2 與產品倉庫；首次建置可連網。固定引擎 commit、來源 SHA256 和既有鎖定建置配方；驗證來源後才建置，不依賴相鄰目錄。
2. 一份使用者配置只填產品網址及模型服務；資料庫密碼、引擎 root 與 publisher key 自動建立。API 不使用 root key。重跑不得重置密碼或資料。
3. 單一 CLI 提供 init、build、up、status、stop、admin；up 先停止寫入者，再遷移、配置引擎及驗證真實向量索引後啟動產品。
4. 模型配置驗證失敗須停止，禁止帶空模型進入假就緒；已初始化引擎禁止無意更換 embedding 模型／端點／維度。
5. 安裝預設使用獨立 Compose project 與資料卷，不接管目前的開發或雲端服務。
6. 統一冷備份涵蓋 PostgreSQL、引擎資料和私密配置；恢復只允許空的隔離環境。舊備份不能直接取代現有生產環境，撤銷／刪除政策回放仍屬生產恢復門檻。
7. 真實驗證：從自動取得的固定來源完成建置，在隔離環境啟動；發布／檢索／刪除、重新啟動與 publisher key 穩定；備份恢復到另一个隔離環境讀回。明確區分模型替身、真模型與尚未驗收項目。

## 邊界

既有 Zeabur 四服務部署與本機開發流程保持可用。此輪交付不自動切換既有資料、不上傳私密配置、不宣稱完成生產災難恢復或同程序整合。升級前做一致性備份；資料庫遷移後不能只換回舊映像就當作回退。
