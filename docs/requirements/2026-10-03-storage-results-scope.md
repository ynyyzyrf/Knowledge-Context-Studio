# 自動存儲與完整結果：本次交付範圍

MAG 於 2026-10-03 確認先做自動存儲與完整結果，暫不做自動收集。本文件優先於 automatic-memory-product.md 的遠期規劃。

## 使用行為

1. 管理員可為 Agent 開啟服務對象記憶的自動存儲。預設維持人工審核；設定不追溯處理既有候選。
2. 個人記憶由擁有者在原有目錄寫入授權中另行開啟自動存儲。Agent 的全域設定不能覆蓋個人擁有者的決定。Skills、peers 維持原流程。
3. 已提交並 commit 的服務對象會話沿用 Worker 提取；有 user 來源的正常候選自動建立正式記憶與發布工作。僅有 assistant/tool/system 來源仍待確認，不能冒充使用者事實。
4. 個人 memories 直接提交的內容完整保存，不再做摘要提取；啟用自動存儲且有寫入權限時直接 active，沿用個人索引。內容仍是 Agent 提交的參考資料，不能視為系統指令。
5. 本期採確定性的相同文字去重，不猜測語意等價或覆寫衝突。不同內容新增；既有版本修改仍沿用人工修改流程。結果不虛報「自動更新」。
6. 同一 external_id / commit key 重試保持冪等；不同 external_id 的個人提交本期不合併，以維持可追蹤的提交回執與寫入權限隔離。
7. 已刪除／停用記憶所引用的舊來源再次被提取時，返回 ignored / source_previously_removed，不保存第二份正文或重新發布。同一舊訊息可能包含多項事實，因此此策略採保守略過；需要恢復內容時應由使用者提供新陳述或走原有人工治理。

## 完整結果

- 任務中心與 Agent job API 顯示執行者、來源快照範圍、處理政策、結果數量、逐條內容與來源 message IDs、正式記憶 ID、當前發布狀態及錯誤。
- 區分提取成功與發布可檢索；零候選明示 no_durable_facts。失敗保留原有重試，不聲稱存儲成功。
- 結果分類 created / deduplicated / review_required / ignored。人工後續操作反映最新狀態；刪除後結果不重新暴露已清除正文。
- 個人提交返回 storage（結果、原因）與 indexing（狀態、錯誤）；重試只返回收據，不因只有寫入授權而洩露後續修改正文。
- MCP 增加 job 結果查詢工具，提交回傳查詢方法；不無限等待背景模型。自動收集未啟用需清楚說明。

## 邊界及驗收

不開發 SDK、hook、模型代理、對話輪詢、自動提交 sessions；不更動生產資料或既有授權。公開介面需兼容現有 Agent。

驗收：人工模式不變；自動模式提交→Worker→發布→同一 Agent 檢索；零結果可辨識；來源不符不自動批准；重複提交不增加正式記憶；撤權後不完成寫入；跨 Agent / tenant 不讀結果；個人寫入者無法讀後續修改內容；發布失敗與完成分開呈現。測試模型與索引替身只能證明契約，不作真實模型、生產容量或雲端已上線的證明。
