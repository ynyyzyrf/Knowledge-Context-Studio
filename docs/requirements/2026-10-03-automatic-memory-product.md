# 自動記憶產品化規格

日期：2026-10-03。狀態：待使用者評審，尚未實作或上線。

本文件保留完整產品願景。使用者已選定先做「自動存儲、完整結果」，自動收集暫緩；本次交付以 [縮小範圍規格](2026-10-03-storage-results-scope.md) 為準。

## 1. 產品目標與成功定義

MAG 要求：外部 Agent 完成接入後，平台自動存儲有價值的記憶，不需要每次要求「幫我記住」，也不需要逐條人工批准一般記憶。

本規格將「全自動」定義為：已授權的對話自動抵達平台，平台自動觸發提取、核對來源、去重、決定新增或更新、持久保存與建立索引；符合自動政策的記憶在下一次授權檢索可用。衝突、來源不足等情況有明確結果，不以強制寫入掩蓋問題。

通用性承諾針對公開接入契約。不能承諾未傳送對話、無任何事件接口、也不能更改模型端點的任意第三方 Agent 都能被自動記錄。接入向導必須在安裝時揭示此限制，不能讓使用者事後靠提醒 Agent 補足。

不新增內置 Agent Runtime；沿用 PostgreSQL 真源、現有 Worker、向量模型與私有 OpenViking。不是本次目標：自動執行 skills、無授權取得第三方歷史對話、直接共享全部人的記憶。

## 2. 現況與缺口（以本機程式為依據）

- `integrations/mag-kb/server.mjs` 提供 stdio tools；寫入依賴 Agent 主動調用。
- `kb_submit_memory_candidate` 寫入 Subject 會話並顯式 commit，返回提取任務；並非正式記憶已生效。
- 個人 sessions 與 memories 分開，`kb_personal_append` 不自動抽取；個人候選需人工審核。
- Subject 記憶與 Person + Space 記憶是不同所有權模型，不能默默搬移或混用。
- 舊接入提示詞要求每次寫入前詢問，與這次的自動化目標衝突，需在接入套件與文件一起替換。
- 目前已刪記憶／文件會週期性重做引擎清理，並產生成功審計。`publication.py`、`document_worker.py` 明確安排成功刪除後再次檢查；因此前次畫面中的重複紀錄不能直接視為 Agent 重複提交或提取失控。需將維護巡檢與產品任務結果分開，保留防止晚到寫入復活資料的保障。

## 3. 接入方案與選擇

| 方案 | 是否能可靠自動捕獲 | 代價／限制 | 本規格用途 |
| --- | --- | --- | --- |
| 對話事件適配器／SDK | 宿主對每輪產生事件且本地持久補傳時可驗收 | 各宿主需一次安裝或少量整合 | 首選，保留原模型與執行流程 |
| 模型記憶閘道 | 經閘道的模型請求及完整回覆可捕獲 | 需更換模型端點；只有支持的協議與流量被覆蓋 | 第二接入途徑 |
| MCP + 持久指令 | 由模型決定是否調用，不能保證每輪觸發 | 遺漏仍可能發生 | 相容模式，明示非可靠自動接入 |

三者共用同一接收、所有權、提取與政策層，禁止各寫一套記憶邏輯。

首批適配器驗收目標為 MAG 正在使用的 Hermes 與 combo 接入端；其可用 hook、事件機制或更換端點方式必須在對應宿主實查，不假設 MCP 安裝就等於 hook 安裝成功。若需要修改其他倉庫，先確認實際執行環境與範圍。

模型閘道首版限定已驗收的協議子集；不以「OpenAI 相容」推論所有推理、工具調用、串流、圖片和其他供應商協議都相容。不得靜默丟欄位或改模型回覆。沒有通過相容性測試的客戶端顯示不支援並改走事件適配器。

## 4. 使用者流程

1. 建立接入連線：指定 Agent、資料所有者、預設 Space、授權範圍及記憶模式。
2. 安裝向導根據能力生成適配器設定／閘道設定／MCP 設定。秘密不輸出到安裝日誌或版本庫。
3. 發送一次合成對話，驗證「收到事件 → 自動提取 → 記憶已啟用 → 檢索命中」，才能標示自動記憶接入完成。
4. 後續照常聊天或執行任務；无需使用者命令寫入，也无需 Agent 自行決定調用記憶工具。
5. 工作台提供記憶列表、來源、版本、最後同步時間與異常；一般記憶不彈逐條批准視窗。

新建連線向導預設建議自動模式，啟用時一次清楚展示被收集的範圍、資料目的地與原文保留設定。既有連線保留原模式，管理員可批次啟用，避免更新後無提示開始收集。

## 5. 統一所有權與模式

- `manual`：保留人工提交／審核。
- `auto_capture_review`：自動捕獲與提取，人工啟用候選。
- `auto_memory`：自動捕獲、提取與政策允許的自動生效；本次核心交付。
- `paused`：停止新收集／自動處理；既有資料讀取是否保留由現有 ACL 決定。

每個新自動接入連線綁定 Tenant + Agent + Person + Space，Person 從產品憑證及伺服器端綁定解析，不相信事件自行指定的身份。共用服務 Agent 若代表多人，需每人獨立產品憑證或受驗證的身份映射，不能全部寫進管理員的私人記憶。

新自動個人記憶以 Person + Space 為唯一目的地，沿用個人目錄索引；多個 Agent 只有獲得同一所有者／Space 的明確權限才可共享。既有 Subject API 保留相容，不自動把 Subject 名称等同 Person。

收集、記憶寫入、記憶讀取及自動生效為可核對的權限／政策；Agent 不能透過工具自行開啟自動生效。撤權和人員停用須在接收與非同步提交結果時重新驗證。

## 6. 事件、觸發與可靠性

提出新增版本化事件接收 API（名稱待實作計畫定案，例如 `POST /v1/memory-events`），事件包含：

- connection、外部 session ID、event ID、來源端序號、角色、正文、事件種類、時間及來源類型。
- 事件種類涵蓋完成訊息、輪次完成、會話完成與明確刪除請求；刪除請求仍須通過現有權限。
- 角色保留 user／assistant／tool，不把 Agent 摘要偽裝成使用者原話。不要上報隱藏推理、系統提示詞或未授權工具輸出。
- Token、Person 與授權目標由服務端校验，API 不接受可任意跨用戶路由的自報 owner。

成功接收只在事件與待處理工作已持久化後回覆 receipt。同一連線下 event ID 重送返回原 receipt；相同 ID 不同內容返回衝突。事件去重與語義記憶去重分開實作。

先接收事件再短時間合併提取：輪次完成為主触發；訊息到達後的持久計時器為兜底，避免宿主漏發 end 事件後永遠不處理。初始建議安靜窗口 15 秒、最長等待 60 秒，作為可調參數與待驗收目標，不是已達成性能。

每個會話保存提取水位與工作版本；每次處理新增訊息及有限前文，避免每輪重提整段歷史。相同窗口工作有唯一約束；多 Worker、超時重領和亂序事件不得漏掉訊息或重複啟用記憶。

適配器需本地持久 outbox、退避、重送及送達確認；只有收到服務端 receipt 才移除。支援明確排除訊息及暫停收集。離線資料的本地保護與保留期限需有配置。

閘道在完成回覆後提交事件，不在串流每個 token 觸發提取；工具中間輪次依已驗收事件格式聚合，未完成或中斷回覆不得標為完成事實。上游錯誤／斷線必須原樣反映，不伪造成功。記憶提取故障不阻塞正常回答；若連原文都未持久收到，必須明示「記憶同步中斷」，不能默默丟失後仍聲稱已記住。

## 7. 自動記憶政策

提取穩定偏好、使用者明確確認的事實／決策、完成且可驗證的工作結果和可重用解法。單纯工具連線成功、閒聊、未確認的推測和短暫報錯通常不形成長期記憶；原文接收成功與長期記憶生成為兩種結果。

流水線：

`事件持久化 → 提取 → 來源／所有權校驗 → 查重與衝突判斷 → 自動新增或版本更新／待確認／忽略 → 索引 → 可檢索`

- 不只依賴模型自報信心。自動啟用需可追溯到有效來源、通過範圍與內容規則，且屬允許的記憶類型。
- 精確重送不新建；等價資訊補充來源而非再建相同記憶。
- 使用者明確更正可以建立新版本並取代舊版；時間較新的模糊陳述不自動等於正確更正。
- 無法確定的矛盾、缺乏來源或敏感資訊，進待確認或拒收；舊有效記憶不能被不確定結果覆寫。
- 憑證、密碼等秘密在接收邊界先排除／遮罩，不得等到已保存原文才僅過濾候選。明確定義安全檢查非百分之百識別所有秘密，提供不收集模式。
- 檢索內容是資料，不具有操作授權；惡意內容不能要求系統擴權、關閉政策或執行 skills。
- 所有自動變更記錄來源、版本、政策版本及系統執行者；索引完成前不宣稱「可語意檢索」。

## 8. 使用者可見結果與運維

接入頁區分：憑證有效、工具可用、自動事件已接通、最近事件、最近自動記憶、索引就緒、錯誤與重試。僅 `kb_health` 成功不能顯示全自動已啟用。

任務結果包含收到訊息數、提取範圍、新增／更新／去重／待確認／忽略數量、處理理由和來源連結。提供可授權查詢的 receipt/job 工具與 API；不存在結果查詢時不能讓 Agent 把接受任務當作已記住。

操作紀錄顯示 Agent 名称、所有者、Space 與維護程序名称，ID 作次要資訊。例行刪除核對記為維護事件或聚合統計，狀態未變時不刷成新的業務完成任務；故障、修復與實際變更仍需保留。不能以減少日誌為由移除晚到索引清理保障。

加入待處理事件量、最老等待時間、模型失敗率、每連線寫入率與花費上限。沿用 PostgreSQL 持久佇列與租約，首階段不為了排程再引入 Redis。超限返回明確可重試訊號，連線間需避免單一 Agent 壓滿全站。

原文保留期限、記憶保留期限與使用者刪除分别可配置；刪除原文時，來源顯示已刪除。停用／刪除記憶立即不再返回，晚到模型或索引工作不得復活資料。來源已刪除時，不得用殘存副本重新提取。

## 9. 交付順序

1. 統一接入身份、模式、事件接收與持久計時觸發，保留既有 API。
2. 自動提取與自動政策、版本化去重更新、結果查詢，接通現有個人索引。
3. 一個真實宿主適配器完成全回路，另以第二種宿主證明契約不是綁死單一 Agent；具體 hook 機制先實查。
4. 接入向導、寫入時間線與異常，更新 MCP 安裝包／描述／持久指令。
5. 需要閘道的客戶端以独立相容性階段交付；不因閘道尚未覆蓋所有協議而把純 MCP 稱為全自動。

先做本機隔離驗證，再以明確啟用的雲端測試連線試運行；不默默改變現有使用者的私人目錄授權與人工模式。

## 10. 必須通過的驗收

- 兩種不同宿主：一次接入後，正常對話表達同一穩定偏好；沒有「記住」指令、沒有模型主動調記憶工具、沒有人工逐條審核，均能自動生成可檢索記憶。
- 使用新的對話並使用不同問法讀回正確事實、來源和版本；若宿主沒有自動檢索接口，明確區分「自動存儲完成」與「自動利用記憶尚未接通」。
- 空內容、閒聊、純接入成功紀錄不強行生成記憶；無候選是可觀測結果。
- 同一事件重送 10 次、新窗口帶重疊歷史，只有一份有效記憶；真正更正生成新版本，模糊衝突不覆寫。
- 亂序、離線補傳、漏發輪次完成、程序重啟、模型超時及 Worker 租約過期均有恢復證據。
- Token 撤銷、資料刪除和模型回覆同時發生時，不得越權或復活已刪記憶。
- Agent／Person／Tenant／Space 隔離與共享授權雙向測試；只讀 Agent 不能開啟收集或自動寫入。
- 閘道另驗證非串流、串流、工具調用、取消、錯誤與不支援內容；不能破壞宿主正常回答。
- 初始目標：健康上游與正常負載時，事件接收至記憶索引可用 p95 <= 120 秒；先測量再決定是否達標。模型超時的例外應獨立報告。
- 30 個 Agent 同時接入的容量驗收固定機型、訊息頻率、資料量與 provider 配額，記錄持續負載／突發負載、p95、隊列回落、成本及錯誤。不得只以 30 個 Token 建立成功宣稱可承載。

## 11. 評審決策

推薦採納：自動化從接收事件開始、普通可靠記憶自動生效、異常例外待確認；MCP 作為讀取與操作工具並保留相容性，不承擔可靠收集的唯一責任。

待規格批准後才進入具體實作計畫及產品程式修改；此文件本身不代表雲端已開啟全自動記憶。
